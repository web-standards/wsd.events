Переменные. Когда и какие?

Условие

  • Значение встречается в коде два и более раз.
  • Значение в будущем может изменяться.

Тип

  • Измерения (размеры, отступы, радиусы скругления и т.п.).
  • Цветовые схемы.
  • Типографика.
  • Наборы иконок.
  • Брейкпойнты.
  • Значение появляется не один раз? Вероятно, двумя появлениями дело не ограничится.
  • Есть шанс, что значение (цвет, длина, размер и т.д.) будет обновляться.
  • Одно из условий удовлетворено? Пора задуматься о заведении переменной.
  • Значение подпадает под один из следующих типов? Смело заводите переменную!
  • Сохраняйте здравый смысл, разумный баланс количества абстракций.

@media

  • На средних и маленьких должна быть компактность.

@media

@media

Inheritance

  • Поговорим о ситуациях, когда состояние блока должно изменяться в зависимости от внешних условий.
  • Таким условием может быть месторасположение блока в DOM'е.

Inheritance

  • Задача. Контрастные цвета кнопки и фона блока.

Inheritance

  • Черный фон — белая кнопка.
  • Воспользуемся каскадом.

Inheritance

			:root {
				--color: black;
			}
			button {
				background: var(--color);
			}
			

				.black-box {
					--color: white;
				}
  • Вынесем значение цвета в переменную.
  • Изменим значение свойства на уровне узла блока с черным фоном.
  • Т.к. работает каскад, применится ближайшее унаследованное значение, при этом на глобальном уровне будет все тот же черный цвет!
  • В SASS это не сработает, т.к. переменные в нем на каскадируются в силу незнания DOM-окружения кнопки.

Inheritance

				:root {
					--color: black;
				}
				selector {
					background: var(--color);
				}
				
					
					selector > selector {
						--color: initial;
					}
  • Отмену наследования переменной можно сделать с помощью значения initial.
  • Т.о. образом потомки не будут пинимать значение переменной.

Inheritance

				* {
					--color: initial;
				}
			
				:root {
					--color: black;
				}
			
				selector {
					--color: black;
				}

  • Несмотря на нулевую специфичность он имее преимущественное применение.
  • Поэтому сбросит вообще все, в т.ч. глобальные переменные.
  • Все что вам останется — локальные ненаследуемые переменные.

Каскад?
Это шутка?

  • Многие возмутяться. Каскад? Что он несет? Каскад это же смертный грех!
  • Несмотря на всеобщую БЭМизацию, жаркие споры и не утихают потому, что иногда от такой возможности сложно отказаться.
  • CSS'у при всех существующих методологиях и подходах все еще не хватает выразительности.

SOLID O

  • Один из основных принципов ООП (принцип открытости/закрытости) провозглашает возможность изменения поведения программной сущности без изменения исходного кода.

SOLID O

Плохо

				.button {
					background: black;
				}
					
				.black-box .button {
					background: white;
				}

Хорошо

				.button {
					background: var(--color,
					black);
				}
				.black-box {
					--color: white;
				}
  • Слева — типичный подход к оформлению по контексту в CSS (селектор потомка).
  • Такой подход нарушает принцип SOLID O: при нем изменяются детали реализации закрытого компонента.
  • В примере справа тот же самый компонент, переписан в соответствии с принципом SOLID O.

Fallback

Fallback

			:root {
				--color:;
			}
				
			.button {
				background: var(--color, black);

  • Fallback — 2-й аргумент функции var().
  • Усложним пример.
  • Есть фреймворк, есть тему по умолчанию, кастомизация через пользовательские свойства.
  • Настройки по умолчанию удобно хранить централизованно, а не локально в каждом компоненте.
  • Перепишем пример.

Fallback

				:root {
					--color:;
					--color-default: black;
				}
					
				.button {
					background: var(--color, var(--color-default));
				}
  • В fallback'е ссылка на пользовательское свойство со значением по умолчанию.
  • Да, можно обращаться к пользовательским свойствам внутри других!

				}
				.button {
					background: var(--color);
				}
  • Поменяв логику переменных можно тот же сценарий реализовать вот так.
  • Да, переменные могут ссылаться друг на друга.

calc()

  • Функции переменных можно использовать с другими CSS-функциями.
  • Особенную мощь предоставляет комбинация с calc().
  • Задача. Расстояние между абзацами должно быть удвоенным размером интерлиньяжа в "px".
  • Изменяется интерлиньяж, изменяется расстояние между абзацами.

calc()

			:root {
				--line-height: 1.5;
				--paragraph-margin: calc(var(--line-height) * 2);
			}
				
			p {
				margin-bottom: calc(var(--paragraph-margin, 0) * 1px);
			}
  • Заводим переменную для хранения значения интерлиньяжа.

calc()

			:root {
				--line-height: 1.5;
				--paragraph-margin: calc(var(--line-height) * 2);
			}
				
			p {
				margin-bottom: calc(var(--paragraph-margin, 0) * 1px);
			}
  • Заводим переменную для расчёта значения отступа между абзацами.

calc()

			:root {
				--line-height: 1.5;
				--paragraph-margin: calc(var(--line-height) * 2);
			}
				
			p {
				margin-bottom: calc(var(--paragraph-margin, 0) * 1px);
			}
  • Присваиваем вычисленному значению единицу измерения.
  • Нельзя к функции var() дописать в конце единицу. Только через calc().
  • Можно было бы вычисление и присвоение единицы измерения объединить в одну функцию. Но это было бы менее наглядно и читабельно.
  • Кроме того, вычисления лучше делать однократно и подставлять результат в нужные места.
  • И удобнее манипулировать с числовыми данными, чем с конкретными значениями. Потому что с числом вы можете делать, что угодно.

JavaScript

  • Работа с переменными препроцессоров в JS похожа на жесткий BDSM.
  • С пользовательскими свойствами это легко и приятно.
  • В одной из версий черновика стандарта было разработано API CSSVariablesMap, но впоследствии удалено из стандарта в поисках лучшего решения.

API CSSStyleDeclaration

Получаем

			getComputedStyle(document.documentElement)
			.getPropertyValue('--variable');

Назначаем

			element.style.setProperty('--variable', 'value');

Удаляем

			element.style.removeProperty('--variable');
  • Т.к. пользовательские свойства обладают всеми особенностями классических свойств CSS, они доступны через API CSSStyleDeclaration.
  • Можно получать значение, задавать его и удалять.

@supports

  • Чтобы разделять код для браузеров с поддержкой пользовательских свойств и без нее, отлично подходит свойство.

@supports

			@supports (--a: 0) {
				/* Progressive Enhancement */
			}
  • Выбираем, какие правила экранируем, а какие делаем основными.
  • В данном случае экранируем стили с поддержкой пользовательских свойств.

@supports

			@supports not (--a: 0) {
				/* Graceful Degradation */
			}
  • И без поддержки.

CSS.supports

  • Если скрипты также опираются на пользовательские свойства CSS…

			if (window.CSS && window.CSS.supports && 
			window.CSS.supports('--a', 0)) {
				// сценарии с поддержкой переменных
			} else {
				// сценарии без поддержки переменных
			}
