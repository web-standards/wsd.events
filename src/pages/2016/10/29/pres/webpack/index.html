Почему Webpack?

По данным https://www.npmjs.com/package/webpack

  • 117 930 загрузок в день
  • 686 388 загрузок в неделю
  • 2 692 853 загрузок в месяц (против 1 994 700 у browserify)
  • 19 835 ★ https://github.com/webpack/webpack
  • 10 360 ★ https://github.com/substack/node-browserify

Почему не Browserify?

  • Browserify отличный и простой инструмент для сборки приложений
  • Есть довольно обширная система расширений (хотя и не такая большая как у webpack)
  • В большинстве случаев необходим Gulp/Grunt для автоматизации процесса сборки

Почему Webpack?

  • Webpack предоставляет огромные возможности для сборки приложений прямо из коробки
  • Больше нет необходимости в Gulp/Grunt
  • Webpack берет весь процесс сборки на себя

Что такое Webpack?

  1. Конфигурационный файл - webpack.config.js
  2. Сборщик
  3. Клиентский скрипт
  4. Загрузчики
  5. Система расширений
  6. Сервер разработки - webpack dev server

Сборщик

  1. Загружает входные файлы и их зависимости
  2. Разбивает код на фрагменты (chunks)
  3. Оптимизирует
  4. Хэширует
  5. Добавляет модуль к сборке

require

			require('path-to-whatever');

Задача: добавлять файл(ы) в сборку динамически

На этапе компиляции доступна переменная logo - имя файла с логотипом. В сборку должен войти только требуемый файл.

Динамический require

			//Directory: './img'
			//Regular expression: /^.*\.svg$/
			require('./img/' + logo + '.svg')

require.context

			let imgContext = require.context('img', true, /\.svg$/);
			imgContext.keys().forEach((key) => {
			    if (key === logo) {
					  imgContext(key);
			    }
			});

Smart Chunks

Chunks - это фрагменты кода, которые загружаются и исполняются по требованию, что позволяет уменьшить размер исходного загружаемого файла и загружать код по по мере необходимости.

Smart Chunks

  • CommonJs - require.ensure(dependencies, callback)
    Загружает, но не исполняет модули.
  • AMD - require(dependencies, callback)
    Загружает и исполняет модули.

Loaders

Loaders

  • Трансформируют содержимое файлов
  • Расширяют базовые возможности webpack
  • Обрабатывают файлы во время require()

Loaders

https://webpack.github.io/docs/list-of-loaders.html - 214 loaders!

Global loaders

			// webpack.config.js
			loaders: {
			  [{ test: /\.less$/, loader: 'style!css!less?noIeCompat' }]	
			}

Global loaders

			loaders: {
			  [{
					test: /\.js$/,
					loader: 'babel-loader',		
					query: {
						presets: ['es2015'],
						cacheDirectory: true
					}	
			}]	
			}

Exports

			//Добавляет в конце модуля
			//module.exports = Handlebars;
			let Handlebars = require('exports?Handlebars!handlebars.js');

Imports

			//Добавляет в начале модуля
			//this.App = window.App;
			require('imports?this.App=>window.App!app.js');

Script loader

			// Загружает модуль 1 раз игнорируя его зависимости
			require('script!awesome-lib.js');

Plugins

  • Трансформируют содержимое файлов
  • Расширяют базовые возможности webpack
  • Работают для всей сборки
  • code->loaders->plugins->output

CommonsChunkPlugin

			//webpack.config.js
			webpackConfig.entry.vendor = ['lodash', 'moment', 'etc'];
			webpackConfig.plugins = [
			  new webpack.optimize.CommonsChunkPlugin(
				'vendor',
				'vendor.js'
				)
			];

ProvidePlugin

			//webpack.config.js
			webpackConfig.plugins = [
			  new webpack.ProvidePlugin({
					Promise: 'bluebird'
				})
			];

BannerPlugin

			//webpack.config.js
			webpackConfig.plugins = [
			  new webpack.BannerPlugin(
					'**Bundle License Code**'
				)
			];

Webpack Dashboard Plugin

Install
npm install webpack-dashboard --save-dev
Use
webpackConfig.plugins = [ new DashboardPlugin() ];
Run
webpack-dashboard -- webpack-dev-server --config ./webpack.config.js

Оптимизация

  • Минимизация - new webpack.optimize.UglifyJsPlugin()
  • Дедубликация - new webpack.optimize.DedupePlugin()
  • Ограничение максимального количества фрагментов кода - new webpack.optimize.LimitChunkCountPlugin({maxChunks: 15})
  • Ограничение максимального размера фрагмента кода - new webpack.optimize.MinChunkSizePlugin({minChunkSize: 10000})

Webpack Dev Server

  • Node.js Express сервер
  • Клиентский код, который соединяется с сервером с помощью Sock.js
  • Сервер отправляет информацию о процессе компиляции на клиент

Webpack Dev Server configuration

		  output: {
	        path: path.resolve(__dirname, "build"),
		    publicPath: "/assets/",
		    filename: "bundle.js"
		  }

Webpack Dev Server launch

$ webpack-dev-server --inline --content-base build/
  • --content-base - директория собранного проекта
  • --inline добавляет скрипт, который обновляет страницу при изменениях

Hot Module Replacement

Обновляет клиентский скрипт без перезагрузки страницы

$ webpack-dev-server --hot --inline --content-base build/

What's next? Webpack 2

  • ES6 модули - import и export без преобразования к CommonJS/AMD
  • System.import - новый способ разделения кода. System.import возвращает Promise и дает возможность отловить ошибки при загрузке модуля.
  • Tree-shaking. Cтатический анализ ES6 модулей во многих случаях позволяет определить на этапе компиляции неиспользуемые модули и не включать их в сборку.
