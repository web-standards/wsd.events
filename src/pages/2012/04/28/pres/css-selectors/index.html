Краткое введение

Все наверняка знают, что такое селекторы…

.content h1 {
	font-size: 1.5em;
	…
	}

Более строгое определение

Селекторы — это конструкции CSS-кода, сопоставляемые с элементами дерева HTML- или XML-документа с целью избирательного выделения в нем тех или иных узлов.

expression ∗ element → boolean

Спецификации

  • CSS1
  • CSS2 и долгожданная рекомендация CSS2.1
  • Selectors Level 3
  • Selectors Level 4

Принципиальные различия селекторов уровней 2, 3 и 4

  • Разнообразие типов селекторов
  • Синтаксис псевдоэлементов
  • Терминология

Псевдоэлементы

CSS2:

E:hover {…}
E:before {…}

CSS3:

E:hover {…}
E::before {…}

Терминологические тонкости. Простой селектор

Пример: div, *, [foo="bar"], .content, #intro, :hover

  • CSS2: a simple selector
  • CSS3: a simple selector
  • CSS4: a simple selector

Терминологические тонкости. Последовательность простых селекторов

Пример: div.content:hover

  • CSS2: a simple selector
  • CSS3: a sequence of simple selectors
  • CSS4: a compound selector

Терминологические тонкости. Комбинированный селектор

Примеры: div p, .menu > a:hover, h1 + p

  • CSS2: a selector = a chain of simple selectors separated by combinators
  • CSS3: selector = a chain of sequences of simple selectors separated by combinators
  • CSS4: a complex selector

Терминологические тонкости. Список селекторов

Пример: h1, h2, h3

  • CSS2: a group of selectors (не считается одним селектором)
  • CSS3: a group of selectors (не считается одним селектором)
  • CSS4: a selector list (считается одним селектором)

Селекторы и производительность

Как браузер обрабатывает загружаемую страницу?

  • HTML — элементы отображаются сразу же по мере получения
  • XHTML — рендеринг происходит только по факту полной загрузки документа

Наглядная демонстрация

Можно понаблюдать за процессом отрисовки страницы по мере ее загрузки в замедленном режиме

Основания для пересчета и возможной перерисовки

  • Первичное отображение документа
  • Изменение размеров
  • Изменения внутри DOM
  • Изменение стилей
  • Срабатывание по таймеру

Как анализируются селекторы?

body section.content h1 {…}

Всегда справа налево!

القاعدة

Является ли текущий элемент заголовком первого уровня?

body section.content h1 {…}

Если да, следуем вверх по DOM, ищем элемент <section> с классом content

body section.content h1 {…}

Нашли? Отлично! Следуем еще выше в поисках <body>

body section.content h1 {…}

Какие селекторы самые быстрые?

Очевидно, те, которые требуют меньше проверок:

#intro {…}
.content {…}

А вот такое будет работать очень-очень медленно, несмотря на селектор по id

#intro * {…}

Такой селектор уже побыстрее

#intro h1 {…}

Здесь выше специфичность крайней справа части комбинированного селектора

Вот такой — еще быстрее

#intro > h1 {…}

В данном случае придется обрабатывать меньшее число узлов DOM

Избыточность не нужна!

header#intro {…}

#intro {…}

Это почти полностью справедливо и для селекторов по классу

Еще один примерчик устранения избыточности

body ul.navigation li a {…}

.navigation a {…}

Общие рекомендации по повышению производительности селекторов

  • Не используйте * справа
  • Делайте селекторы максимально специфичными
  • Устраняйте избыточные уточнения
  • Вместо комбинированных селекторов используйте селекторы по классу

См. Google Page Speed

И последние станут первыми?

Странное, казалось бы, дело:

  • E:first-child — определен в CSS2
  • E:last-child — описан только в CSS3 и реализован в браузерах намного позже

Второй при «честной» реализации требует больше ресурсов

E:last-child не везде реализован «честно»

Можно сравнить отрисовку меню навигации в замедленном режиме в различных браузерах

  • «Честная» реализация: Firefox, IE
  • «Нечестная» реализация: Chrome, Safari, Opera

Все лучшее — детям?

Давно и успешно реализованы:

  • div p — селектор потомка
  • div > p — селектор дочернего элемента, то есть прямого потомка

Рассчитывать ли нам на селектор предка или селектор родителя?

  • div:has(p) — существует в jQuery

Как это может выглядеть? Код разметки

<section class="content">
	<h1>Заголовок</h1>
	<p>Текст первого абзаца.</p>
	…
	<p>Текст еще какого-то абзаца с <code>фрагментом кода</code>.</p>
	…
</section>

Как это может выглядеть? Код таблицы стилей

.content:has(code) {
	line-height: 1.5em;
 }

Условия установления применимости правила

  • Обнаружен первый вложенный элемент <code>
  • Полностью загружены все элементы, находящиеся внутри <section>

Дополнительные проблемы

  • Как только встретится <code>, потребуется перерисовать <section>
  • Применение правила затрагивает наследуемые свойства ⇒ производится перерасчет и перерисовка каждого потомка элемента <section>

Целевые объекты селектора

По умолчанию subjects определяются крайней справа частью селектора:

.content pre code {…}

Принудительное переопределение целевых объектов

ol > li:only-child {…}

ol! > li:only-child {…}

Одна и та же структура DOM-дерева, но различные целевые объекты

Тестирование производительности

Как выяснить порядок различий?

  • Сгенерируем несколько документов
  • Структура документов — «как в жизни»
  • Разметка — одна, внешний вид — один, наборы селекторов — разные
  • Объем каждого файла — чуть более 300 килобайт
  • Каждый документ содержит 3000 элементов <p>
  • Каждая таблица стилей включает 300 CSS-правил

Устройство тестовых файлов

<div id="d1" class="d1">
	<section id="s1" class="s1">
		<article id="a1" class="a1">
			<p id="p1" class="p1"><span>Текст абзаца 1.</span></p>
			… еще 9
		</article>
		… еще 9
	</section>
	… еще 5
</div>
… еще 4

Методика измерения

Перед таблицей стилей, внутри <head>…</head>:

var $startTime = (new Date()).getTime();

Перед закрывающим тегом </body>:

window.onload = function() {
	var $processDuration = (new Date()).getTime() - $startTime;
}

Собственно, пища для размышлений

  • Тест 0 — без стилей
  • Тест 1 — #foo
  • Тест 2 — .foo
  • Тест 3 — .foo > span
  • Тест 4 — .foo *
  • Тест 5 — .bar p:last-child
  • Тест 6 — .bar p:nth-child(-11n+10)
  • Тест 7 — .bar p:nth-of-type(-11n+10)

Профайлеры

  • Позволяют детально протоколировать все события, связанные с обработкой кода разметки и таблиц стилей, с применением селекторов, с перерасчетом и перерисовкой элементов страницы
  • Существуют для Opera и для Webkit
  • Интересно сопоставить результаты наших тестов с тем, что фиксируется профайлерами

Краткие выводы по результатам тестов

  • «Хорошие» селекторы: почти незаметный вклад в «торможение» даже при изрядном количестве правил
  • «Плохие» селекторы: способны замедлить процесс в разы
  • Одно правило с «плохим» селектором порой сто́ит сотни правил с «хорошими»

Каскадность vs. независимость

Наследование

body {
	font-size: 16px;
	}
.content h1 {
	font-size: 1.5em;
	}

Детально описывается в CSS2.1

Каскад

abbr {
	border-bottom: dotted .1em;
	}
h1 abbr {
	border-bottom: none;
	}

Детально описывается в CSS2.1

Специфичность

  • a — количество селекторов по идентификаторам
  • b — количество селекторов по классам, по атрибутам, по псевдоклассам
  • с — количество селекторов по типу элемента («по тегу»), по псевдоэлементам

«Звездочка» игнорируется, :not сам по себе не рассматривается как псевдокласс

Примеры вычисления специфичности

Прямая цитата из спецификации Selectors Level 3:

*              /* a=0 b=0 c=0 -> specificity =   0 */
li             /* a=0 b=0 c=1 -> specificity =   1 */
ul li          /* a=0 b=0 c=2 -> specificity =   2 */
ul ol + li     /* a=0 b=0 c=3 -> specificity =   3 */
h1 + *[rel=up] /* a=0 b=1 c=1 -> specificity =  11 */
ul ol li.red   /* a=0 b=1 c=3 -> specificity =  13 */
li.red.level   /* a=0 b=2 c=1 -> specificity =  21 */
#x34y          /* a=1 b=0 c=0 -> specificity = 100 */
#s12:not(foo)  /* a=1 b=0 c=1 -> specificity = 101 */

Верстка независимыми блоками в идеале

  • Никакие изменения в стилях одного блока никак не влияют на другой
  • Минимальное использование наследуемых свойств
  • Никакого каскада
  • Только простые селекторы по классу и никакие более

Область применения

  • Всем тут знакома методология БЭМ
  • Она хороша для проектов масштаба «Яндекса», но таковых в Интернете около 0%
  • При разработке меньших по масштабу проектов не мешало бы включать здравый смысл
  • Наследование, каскад — базовые механизмы CSS, которые вряд ли нужно игнорировать совсем

Собственно, о здравом смысле

Google Page Speed рекомендует:

ul li {color: blue;}
ol li {color: red;}

.unordered-list-item {color: blue;}
.ordered-list-item {color: red;}

Семантика?.. Объем HTML-кода?..

Вполне нормальная практика

.content h1 {
	…
	}

	}

Слабое место

Переопределить объявления, соответствующие селектору с высокой специфичностью:

.content p {margin-bottom: 1em;}

…можно только за счет еще более высокой специфичности:

.content .special {margin-bottom: 0;}

Тоже вполне нормальная практика

#intro {
	…
	}

Идентификаторы или классы?

  • Одинаковая производительность
  • У селектора по классу меньшая специфичность
  • id уникален

Что именно использовать? Решайте сами в зависимости от задачи!

Избранные новшества Selectors Level 3

Структурные псевдоклассы nth-…

Выбираем нечетные элементы:

E:nth-child(odd) {…}

Четные:

E:nth-child(even) {…}

Более сложные аргументы

Первый пример. E:nth-child(2n)

Второй пример. E:nth-child(5)

Более сложные аргументы

Третий пример. E:nth-child(3n+5)

Четвертый пример. E:nth-child(3n-5)

Более сложные аргументы

Пятый пример. E:nth-child(-4n+9)

Ну и хватит. Хорошего понемножку. :-)

Вспоминаем матан!

Аргумент — последовательность c(n) = an + b, где n — неотрицательное целое, a и b — целые

E:nth-child(2n) {…} /* 0-й, 2-й, 4-й, 6-й, … */
E:nth-child(5) {…} /* только 5-й */
E:nth-child(3n+5) {…} /* 5-й, 8-й, 11-й, … */
E:nth-child(3n-5) {…} /* -5-й, -2-й, 1-й, 4-й, 7-й, … */
E:nth-child(-4n+9) {…} /* 9-й, 5-й, 1-й, -3-й, … */

Будьте внимательны!

CSS:

.content p:nth-child(even) {…}

HTML:

<section class="content">
	<h1>Заголовок</h1>
	<p>Текст первого абзаца.</p>
	<pre><code>Образец кода</code></pre>
	<p>Текст второго абзаца.</p>
</section>
