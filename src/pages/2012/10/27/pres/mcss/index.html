Компоновка модулей

По полочкам

Стили каждого модуля хранятся в одном месте, включая каскад: 
/* Toolbar
--------------------------------------------------------------------- */

.toolbar {...}
	.toolbar_logo {...}

/* Toolbar dropdown menu
-------------------------------------------------- */

.toolbar_dropdown {...}
	.toolbar_dropdown .u-menu {...}

/* /Toolbar dropdown menu */

/* /Toolbar
--------------------------------------------------------------------- */

Контекст - исключение

Единственное исключение, это классы Контекстного слоя: 
/* Toolbar
--------------------------------------------------------------------- */

	...

/* Toolbar dropdown menu
-------------------------------------------------- */

.toolbar_dropdown {...}
	.ie8 .toolbar_dropdown {...}
		.toolbar_dropdown .u-menu {...}

		@media all and (...) {
			.toolbar_dropdown .u-menu {...}
			}

/* /Toolbar dropdown menu */

/* /Toolbar
--------------------------------------------------------------------- */

Именование

Уникальные названия, на основе модуля
Названия классов отделяются "_", а модификаторы "__"
<header class="toolbar">
	<a href="/" class="toolbar_logo">Logo</a>
	<nav class="toolbar_dropdown">
		<ul class="toolbar_dropdown_ul">
			<li class="toolbar_dropdown_li">
			<li class="toolbar_dropdown_li toolbar_dropdown_li__active">

<menu class="umenu">
	<li class="umenu_i">
	<li class="umenu_i umenu_i__active">
	<li class="umenu_i umenu_i__special">

Фундамент

Корневые, мало изменяемые стили:
  • ресеты
  • стили по умолчанию
  • общая конструкция

Основные правила:

  • Малый вес селекторов, располагаются в самом начале CSS

Контекст

  • .ie8 - браузеры
  • .touch - особенности девайса
  • .logged-in - среда
  • Media queries

Основные правила:

  • Располагаются рядом с модифицируемыми классами, по всему CSS

1 слой - Базовый

Портальный фреймворк

например:
  • формы
  • кнопки
  • блоки навигации и пр.
Можно использовать Twitter Bootstrap, 960gs, inuit.css

1 слой - Базовый

Основные правила:

  • Абстрактность названий и модификаторов
  • Модифицируются каскадом от 2 и 1 слоя
  • Располагаются вверху css

Преимущества:

  • Переиспользуемость
  • Простая поддержка
  • Быстрая разработка

2 слой - Проектный

Изолированные модули, составные части страницы

например:
  • форма регистрации
  • блок логина
  • корзина товаров

2 слой - Проектный

Основные правила:

  • Уникальные названия частей модуля
  • Модифицируются только от 2 слоя
  • Располагаются между стилями 1 и 3 уровня

Преимущества

  • Изолированность
  • Большой доступ к частям модуля

3 слой - Косметический

Простые, мало влияющие стили

например:
  • цвета ссылок
  • низкоуровневый OOCSS (.font-size-xl, .margin-t-l)
  • глобальные модификаторы

3 слой - Косметический

Основные правила:

  • Независимость от других слоёв (кроме контекста)
  • OOCSS для блоков вне проектов, не больше 3 классов на блок
  • Большой вес селекторов, располагаются в самом низу CSS

Преимущества:

  • Малое влияние на вёрстку страницы
  • Экономия на кол-ве модулей
  • Простота работы

Процесс разработки

База стандартов

Разработка нового интерфейса

Набрасываем каркас 1 слой

<form class="form">
	<div class="info-block">Заполните поля</div>
	<input type="text" class="input-text">
	<a href="#">Помощь</a>

Создаём новый проектный модуль 2 слой

<fieldset class="new-p-module">
	<form class="new-p-module_form form">
		<div class="new-p-module_tip info-block">Заполните поля</div>
		<input type="text" class="new-p-module_input-text input-text">
		<a href="#">Помощь</a>

Зачем еще один велосипед?

MCSS vs БЭМ

  • Есть правила взаимодействия модулей - слои
  • Адекватный уровень абстрактности
  • Легко использовать без спец. инструментов

MCSS vs SMACSS

  • Базовый слой с переиспользуемыми стандартами
  • Более независимые модули и блоки
